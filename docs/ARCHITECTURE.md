## หลักการสำคัญ

**เงินเป็นจำนวนเต็มสตางค์ทุกที่** — ทั้งฐานข้อมูล API และหน้าเว็บ แปลงเป็นบาทเฉพาะตอนแสดงผล
`calcTotals` / `settlePayments` (apps/api/src/common/money.ts) เป็นจุดเดียวที่คำนวณยอดและตรวจการชำระ

**Snapshot ราคา** — `order_items` เก็บชื่อและราคา ณ เวลาขาย แก้เมนูภายหลังไม่กระทบบิลเก่า

**Idempotency** — ทุกบิลมี `clientId` (UUID ที่เครื่องสร้าง) และ unique `(branchId, clientId)`
เครื่อง POS จึงส่งซ้ำได้ไม่จำกัดโดยไม่เกิดบิลซ้ำ

**ความถูกต้องเมื่อทำงานพร้อมกัน**
- เพิ่มรายการ/ชำระ/ยกเลิก ล็อกแถวออเดอร์ (`SELECT … FOR UPDATE`) ในทรานแซกชัน
- partial unique index: โต๊ะละ 1 บิลที่สถานะ `open`
- เลขที่บิล `สาขา-YYYYMMDD-NNNN` จากตัวนับรายวันแบบ atomic (`INSERT … ON CONFLICT … RETURNING`)

## สองเส้นทางการขาย

| | ขายหน้าร้าน / กลับบ้าน | ทานที่ร้าน (โต๊ะ) |
|---|---|---|
| ออฟไลน์ | ✅ บันทึกลง IndexedDB ก่อน แล้ว `POST /sync/orders` | ❌ ต้องออนไลน์ (บิลเปิดใช้ร่วมหลายเครื่อง) |
| ราคา | ใช้ราคา snapshot จากเครื่อง (ลูกค้าจ่ายตามนั้นจริง) — บันทึก audit ถ้าต่างจากราคาปัจจุบัน | ราคาจากเซิร์ฟเวอร์ |
| เวลา | `occurredAt` จากเครื่อง (ถ้าล้ำอนาคตเกิน 5 นาทีใช้เวลาเซิร์ฟเวอร์) | เวลาเซิร์ฟเวอร์ |
| กะ | ผูกกับกะที่ครอบคลุมเวลาขายจริง | กะที่เปิดอยู่ตอนชำระ |

ผลการซิงค์รายบิล: `created` / `duplicate` → ลบจากคิว, `rejected` → ย้ายไปหน้า "การซิงค์" ให้ผู้จัดการตรวจ (ไม่ลบเอง)
